# 分组隐藏计费倍率

本仓库在管理员分组的高级创建、编辑表单中，在“费率倍数”下方增加“隐藏倍率”。该字段仅供管理员配置，用来替换实际计费的基础倍率；用户看到的分组费率及用户专属费率仍按公开配置显示。

## 配置与优先级

- 不填写或清空隐藏倍率：使用原有的用户专属倍率、分组费率和系统默认规则。
- 填写隐藏倍率：实际计费基础倍率优先采用隐藏值，覆盖用户专属倍率及公开分组倍率。
- 有效范围为 `0.0001` 至 `999999.9999`，数据库保存四位小数。`0` 不是清空，也不是免费倍率，会返回参数错误。建议输入不超过四位小数。
- 普通 token 计费在基础倍率上继续乘以请求计价时刻的高峰因子。
- 图片、视频启用独立倍率时，仍优先使用各自独立倍率；未启用时继承实际基础倍率。按次媒体计费不额外套用 token 高峰因子。
- 批量图片沿用既有折扣、账号倍率及预扣规则，只替换分组实际基础倍率；独立图片倍率仍优先。

实际基础倍率顺序：

```text
隐藏倍率 > 用户专属分组倍率 > 分组公开费率 > 系统默认倍率
```

隐藏倍率直接替换基础倍率，不与公开分组费率相乘。例如公开倍率为 `2`，用户专属为 `1.5`，隐藏倍率为 `0.8`，高峰因子为 `1.25`：token 实际倍率是 `0.8 × 1.25 = 1`，用户使用记录显示的倍率是 `1.5 × 1.25 = 1.875`。清空隐藏倍率后实际倍率恢复为 `1.875`。若启用图片独立倍率 `0.6`，按次图片仍使用 `0.6`。

## 管理员 API

管理员分组响应包含可空的 `hidden_rate_multiplier`。公共分组 DTO、用户分组列表、订阅和 API Key 中的公共分组信息不增加此字段。

创建分组时，可省略该字段或传 `null`；传数字则保存隐藏倍率。

更新分组时采用部分更新语义：

| JSON 内容 | 行为 |
| --- | --- |
| 不包含 `hidden_rate_multiplier` | 保留原配置 |
| `"hidden_rate_multiplier": null` | 清空并恢复原计费规则 |
| `"hidden_rate_multiplier": 0.8` | 更新实际基础倍率为 `0.8` |

复制分组会复制隐藏倍率。Simple 模式维持既有的基础字段白名单，不提供隐藏倍率编辑，也不会因基础资料编辑而清除原值。管理员用户费率弹窗仍能维护公开专属费率，预览会提示实际基础倍率受到隐藏配置的覆盖。

## 使用记录与金额

每条新使用记录分别保存：

- `rate_multiplier`：实际计费倍率，管理员使用记录继续读取此值。
- `display_rate_multiplier`：请求计价时刻的公开展示倍率快照，用户使用记录通过原有的 `rate_multiplier` API 字段读取该快照。

公开展示快照使用同一请求计价时刻的用户专属或分组公开倍率、相应高峰因子和媒体规则。之后修改公开费率或隐藏倍率，不会改写历史展示快照。未配置隐藏倍率时也保存展示快照。历史记录的快照保留 `NULL`，继续显示原有历史实际倍率，不按当前配置推算。

批量图片在提交时保存公开分组/用户倍率与批量折扣的最终展示倍率，结算时复制到使用记录；实际价格和冻结余额按实际倍率快照处理。已有批量任务的展示快照为 `NULL`，结算后保留历史回退行为。

消费金额、余额、订阅额度、API Key 配额及管理员成本统计均保留真实扣费结果。隐藏配置本身不在用户接口中暴露，但用户仍可能通过实际消费金额推算折扣；此功能不伪造消费金额。公开 `/v1/sub2api/billing` 继续返回公开费率语义。

## 调度、预扣与缓存

普通网关、OpenAI 网关、在途预扣、利润准入和利润预演都使用相同的实际基础倍率优先级。组合分组及 fallback 路径沿用原有计费归属：以计费所属分组计算实际倍率，不以调度成员的公开倍率替代。

公开用户费率解析缓存只缓存用户覆盖值或“无覆盖”，不会缓存隐藏值或冻结分组默认值；清空隐藏配置后能够恢复当前公开计费规则。API Key 认证缓存快照版本升级为 `25`，包含隐藏倍率；旧版本回源重建。分组更新沿用认证缓存失效机制，数据库直接修改隐藏倍率也会通过持久化失效队列触发刷新，刷新时序与现有分组计费字段一致。

离线 `profit-preview` JSON 导入支持分组字段 `hidden_rate_multiplier`，使预演的默认及最低有效倍率与实际准入一致。

## 验证与验收

本次新增回归覆盖管理员创建/更新/显式清空/复制及输入边界，认证缓存 JSON 往返和旧版本淘汰，用户 DTO 隐藏字段隔离、历史回退与真实金额保留，公开倍率缓存的默认值刷新，两类网关实际扣费与公开快照、高峰、独立图片/视频、预扣和组合分组利润准入，以及批量图片提交和结算快照。

从仓库根目录可执行前端 CI 检查和生产构建：

```bash
make test-frontend
pnpm --dir frontend run build
```

从 `backend` 目录可执行后端单元测试和内嵌前端构建；后者需先完成前端构建：

```bash
go test -tags unit ./...
go build -tags embed ./...
# 仅验证本功能的实际计费，以及批量图片从提交到结算的服务回归
go test -tags unit ./internal/service -run '^TestHiddenRate(Batch|Billing)_' -count=1
# 有可用 Docker 的环境补跑数据库等集成测试
go test -tags integration ./...
```

推荐手动验收：

1. 新建分组，公开倍率填 `2`、隐藏倍率留空；使用用户倍率 `1.5` 发起一次 token 请求，确认正常扣费。
2. 隐藏倍率改为 `0.8`，再次请求；管理员使用记录应为实际倍率，用户使用记录应保持公开倍率，实际余额扣减与管理员一致。
3. 启用高峰因子 `1.25`，在高峰时段请求，验证实际 `1`、用户展示 `1.875`。
4. 配置独立图片或视频倍率，确认该倍率优先；批量图片验证折扣、冻结及结算。
5. 清空隐藏倍率，确认恢复公开规则；修改分组公开倍率，确认已产生的使用记录展示不变。
6. 检查用户分组、API Key、订阅及用量 JSON，不出现隐藏配置字段；管理员分组 API 包含正确数值或 `null`。

本地无法使用 Docker 时，数据库集成测试仅能确认编译，需在有 PostgreSQL/Redis 集成测试环境的 CI 或服务器中补跑。真实 GitHub Actions 发布和部署不属于本地单元测试覆盖范围。
